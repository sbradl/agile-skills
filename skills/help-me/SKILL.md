Read [`../../WORKING-AGREEMENT.md`](../../WORKING-AGREEMENT.md) first; it governs this run.

The user calls this at any point, also in the middle of another skill. The thinking comes first and is the user's, and so is the decision: you lay out the options and leave the pick to them.

## Steps

1. **Take stock.** Work out where the session stands: the skill and step in progress, what is decided, what is still open. Tell the user in a line or two.
2. **Guiding questions.** Ask the questions whose answers would steer the next step, the one that matters most first. They follow the working agreement's open-question rule: one per message, the question alone.
   Done after three questions, or earlier when the user asks for the options.
3. **Options.** Give the options for what to do next as the working agreement's options table, built on the user's answers.
4. **Return.** The user chooses. When another skill was in progress, continue it where it stood, with the choice applied.
